今天这篇围绕《数据结构》里"字符串查找及数组矩阵压缩"这一块整理。压缩矩阵这类题目的本质是：**大量重复或有规律的存储不值得原样铺满，要按规律只存一份**。常见三兄弟：

| 矩阵 | 特点 | 压缩思路 | 状态 |
| --- | --- | --- | --- |
| 对称矩阵 | a\[i\]\[j\] = a\[j\]\[i\] | 只存上/下三角，n×n → n(n+1)/2 | ✅ 已实现、可演示 |
| 三角矩阵 | 对角线一侧全是常量 c | 只存三角区（可选 +1 格存常量 c） | ⬜ 未写 |
| 稀疏矩阵（系数矩阵） | 非零元远少于 n² | 三元组 (i, j, value) / 十字链表 | ⬜ 未写 |

## 1. 对称矩阵压缩（已完成 ✅）

**原理**：对称矩阵满足 a\[i\]\[j\] == a\[j\]\[i\]，所以一整片镜像区域是多余的，只存下三角（含对角线）即可：

- 原始 n×n 要存 n² 个；
- 压缩后只需 **n(n+1)/2** 个——n=3 时 9 → 6，n=10 时 100 → 55，省将近一半。

**实现位置**（`Array2D<T>`，配套 `Array1D<T>`）：

```cpp
bool IsSymmetricTriangularMatrix();                 // 校验是否对称（且填满）
Array1D<T> ZipSymmetricTriangularMatrix();          // 把下三角按行压成一维
Array2D<T> UnZipSymmetricTriangularMatrix(const Array1D<T> &Zip); // 解回全矩阵
```

- **Zip**：按行 i，取 j ≤ i 的元素 `(i, j)` 依序 push 进一维，长度恰为 n(n+1)/2；
- **UnZip**：从一维按序取回，写到 `idx1 = i*n + j`，再对称回填 `idx2 = j*n + i`，把镜像补全；
- 一维下标 k 与 (i, j) 的换算就是这类题的考点：行优先存下三角时 k = i(i+1)/2 + j（工程里用循环 push 实现，效果等价）。

**踩过的真 bug**：`UnZip` 把整个矩阵用 `SetDataInArray` 写满了，却没同步 `CurDataUnitNumber`（容器计数仍是 0）——结果**解压出来的矩阵“看起来是空的”**，对称检查也通不过。修法就一行：解压完把计数置为 n²。教训：**压缩/解压不只是搬数据，数据与“计数/长度”必须同步**。

**验证**：n=3 对称阵 `[[1,2,3],[2,4,6],[3,6,9]]` → 压缩成 6 个 → 解压回 9 个 → 逐位与原矩阵比对，完全一致 ✔。

## 2. 三角矩阵压缩（计划 ⬜ 未写）

下（上）三角矩阵：主对角线另一侧**全是同一个常量 c**。

- 只存三角区，元素个数也是 n(n+1)/2；
- 两种存法要区分：① 不含对角线上方的常量 → 正好 n(n+1)/2；② 若要把常量 c 也"显式"存下来 → 需 +1 格；
- 下标换算与对称矩阵同款（一行一行的三角序号），关键是**别把三角区外那部分真去铺 n² 个格子**。

## 3. 稀疏矩阵（系数矩阵）压缩（计划 ⬜ 未写）

稀疏：非零元素数量远小于 n²。继续铺 n×n 数组就浪费了，压缩的目标是**只存非零元 + 它们的位置**。教材里的三档做法：

1. **三元组顺序表**：一维存 `(row, col, value)`，按行优先排；配套转置、快速转置；
2. **行逻辑链接的顺序表**：在三元组上再加"每行第一个非零元位置"数组，按行取更快；
3. **十字链表**：行/列两条链，插入删除频繁时更灵活（考研常考概念，写代码重）。
