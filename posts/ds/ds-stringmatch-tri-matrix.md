## 1. 判定：主对角线把矩阵分成两半，问"哪一半是清一色"

课堂只讲了"什么是三角矩阵、怎么压缩"，没讲**怎么判定一个陌生矩阵是不是**。自己理出来的思路一句话：

> 主对角线把除对角线外的格子分成右上(i<j)、左下(i>j)两片；**下三角矩阵 = 右上片整片同一个值，上三角矩阵 = 左下片整片同一个值**。

- "下三角矩阵"名字里的"下"，指的是**真数据在下三角（含对角线）**，它牺牲的是右上那片——所以判定它反而要**只扫右上区**；
- 反之判上三角矩阵只扫左下区。

**判定函数的难点不是扫描，而是结果里必须带回两个信息：方向 + 常量 c。** 对称矩阵自说明（上下互为镜像、存哪半都行）；三角矩阵不带上"常量区在哪侧、c 是多少"，Zip 不知道存哪半、UnZip 不知道拿什么填另一半。工程签名：`UnderTriangularMatrix(T &Constant, bool DetectMode)`，mode=false 验下三角、true 验上三角。

扫描范围（行优先）：

- 验下三角（右上区）：外层 `i` 从 0 起，内层 **`j` 从 `i+1` 起**——每行起点都不同，因为 (i,i) 是对角线真数据，它右边的格子才属于候选常量区；
- 验上三角（左下区）：外层 `i` 从 1 起，内层 `j` 到 `i-1` 止，互为镜像。

**边界与退化**：

- n==1：右上/左下两片都为空，怎么判都成立（先把单元素矩阵的判定提到取基准**之前**，否则 (0,1) 越界）；
- **全常量矩阵（如全 7）会让两种判定同时成立**——它同时是"下三角"也是"上三角"。这不是 bug，是这些特殊矩阵本来就**嵌套**（常量矩阵还是对称矩阵、对角矩阵）；需要单一答案时约定"先下后上"即可。

复杂度：右上区共 n(n−1)/2 格，全部看完才能下结论，O(n²)。但输入本身就有 n² 个数，所以这是"线性于输入量"，已是下界，没有更快的余地。

## 2. Zip：真三角区 + 1 格常量，长度 n(n+1)/2 + 1

压缩格式定成 **`[真三角区 n(n+1)/2 个（行优先）] + [末格 = 常量 c]`**。

这里和对称压缩有个**本质区别**，也是最初写错的地方：对称解压时，镜像数据能从压缩数组**自己长出来**（回填 (j,i) = (i,j) 的值即可），不需要任何额外信息；而三角矩阵的常量区内容 c **不在三角区里**，压缩结果不带上它，UnZip 就无从还原。所以必须多存 1 格——这就是"两种存法（±1 格）"里选"含 c"的原因。

```cpp
Array1D<T> ZipTriangularMatrix(bool DetectMode) {
    T Constant{};
    if (!UnderTriangularMatrix(Constant, DetectMode)) return Array1D<T>(0);
    Array1D<T> Ziped(n * (n + 1) / 2 + 1);      // 容量预分配，防止默认容量静默丢数据
    // mode=false: 存下三角 i 从0起、j<=i；mode=true: 存上三角 i 从0起、j>=i
    Ziped.PushDataInArray(Constant);            // 末格 = c
    return Ziped;
}
```


顺序验证过：Zip 压真三角区是"行 i 升序、列按区域升序"，UnZip 按行优先填真数据格时命中顺序与之一致，所以游标从头取就天然对上，**一行下标公式都不用算**。

## 4. 与对称压缩的对比（考试最爱考）

| 维度 | 对称矩阵 | 三角矩阵 |
| --- | --- | --- |
| 冗余来源 | 上下互为镜像 a[i][j]==a[j][i] | 一侧整片同一常量 c |
| 存的个数 | n(n+1)/2 | n(n+1)/2 **+1**（多那格是 c） |
| 不存的那半 | 镜像区——真数据，可由存储推导 | 常量区——就一个 c，需显式携带 |
| 解压动作 | 回填**镜像副本** | 区外**广播同一个 c** |
| 判定要点 | 对称自说明，一个 bool 足够 | 必须带回"方向 + c" |

## 5. 手写过程踩过的坑（比算法本身值钱）

1. **相等就 return true**——第一个格子等于基准就放行，后面的乱子全被跳过；正确是"遇到不等立刻 false，**全扫完没不等才 true**"。
2. **`j = i++`**——内层初始化里 i++ 偷改了外层 i：行会跳、列起点错、扫进对角线。要 `j = i + 1`。
3. **n==1 判在取基准 (0,1) 之后**——单元素矩阵 (0,1) 越界读，未定义行为。退化判断必须先于取基准。
4. **模板里写 `int UselessData = 0`**——T=std::string 时编译不过，要 `T Constant{};`。
5. **`Array1D` 默认容量 50**——n=10 时三角区要 55 格，Push 静默失败丢数据；必须按 n(n+1)/2+1 预分配并检查 Push 返回值。
6. **UnZip 从 `DataArea`（原矩阵）取数**——等于复制原矩阵，压缩数组根本没被用上；数据源必须是 `Zipped`。写解压前先问自己"我读的这份数据是从压缩数组来的吗"。
7. **`switch (bool)`**——能用但编译器警告 `-Wswitch-bool`，改成 if/else 更干净。

## 6. 交互演示（main 菜单新增第 4 项）

容器菜单新增 `4) Array2D<T> 二维三角矩阵`，内部支持 4 种生成方式：

1. **下三角矩阵**（右上区全 0）→ 应命中下三角判定；
2. **上三角矩阵**（左下区全 0）→ 应命中上三角判定；
3. **全常量矩阵**（全 7）→ 演示"退化矩阵两种判定都成立"的嵌套情形；
4. **手动逐格输入任意矩阵** → 普通矩阵应被两种判定同时拒绝，验证稳健性。

每次自动跑完整闭环：生成 → 网格打印 → **双向判定（分别报 c）** → Zip（打印压缩数组）→ UnZip → 逐格比对还原校验。

三个实测结果（int，n=3，压缩长度 7 = 3·4/2+1）：

- 下三角 `[1 0 0; 2 4 0; 3 6 9]` → 压缩 `[1,2,4,3,6,9,0]`（末格 0 是 c）→ 还原一致 ✔；
- 全常量 7 → 下/上判定都"是 ✔ c=7"，还原一致 ✔；
- 手动输入 1..9 普通矩阵 → 两种判定都"否"，正确跳过压缩 ✔。
